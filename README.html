new-mailings · Claude Code

Flujo de Mailings

Cómo pasamos dos diseños de Figma (inglés y español) a correos HTML listos para cada ambiente. Cada módulo es un proyecto, hay una carpeta por etapa y una subcarpeta por idioma, y todo se mueve con tres skills.

Node + npm install MCP de Figma conectado Microsoft Edge Imágenes .png / .jpg
PASO 1/maquetar-figma

Figma EN + ES → maqueta por idioma e imágenes .png/.jpg.

 PASO 2/entregar-dev

HTML con URLs de PRD para el desarrollador.

 PASO 3/publicar-ambientes

Una versión por ambiente (dev, qa, prd) e idioma.
Organización

Un proyecto por módulo

Cada maquetador recibe un Figma con los mailings de un módulo, por ejemplo alerts. Cada módulo es un proyecto: una carpeta mailings-<nombre>/ en la raíz del repositorio. /maquetar-figma pregunta el proyecto: si la carpeta existe, trabaja ahí mismo; si no, la crea con todas sus subcarpetas.

mailings-alerts/un proyecto = un módulo
├─proyecto.json{ "nombre": "alerts", "carpetaImagenes": "alerts/" }
├─1_maqueta/en·esmaquetas + .txt de observaciones
├─2_entrega/en·esHTML para el desarrollador
├─3_integrado/en·esHTML devuelto con variables
├─4_bucket/dev·qa·prdversión final por ambiente e idioma
├─img/solo .png/.jpg optimizados del proyecto
├─trash/papelera
└─obs/observaciones para producto (HTML con fecha, Word)
ref/referencias compartidas por todos los proyectos
scripts/optimizar.mjs · rutas.mjs · proyecto.mjs
ambientes.jsonURLs de dev, qa y prd (comunes a todos)

Carpeta destino de imágenes

En el repo del bucket, las imágenes de cada proyecto no van sueltas en img/: van en una subcarpeta propia. Esa subcarpeta se guarda en proyecto.json como carpetaImagenes. /maquetar-figma la pregunta la primera vez y después solo pide confirmarla. La URL de /entregar-dev y /publicar-ambientes se arma así:

Ambiente · ambientes.jsonhttps://itl-0003-portal-dev-s3-pub-templates-03.s3.eu-south-2.amazonaws.com/img/ + proyecto.jsonalerts/ + Imagene-logo-incontrol.png

Por eso, al subir las imágenes al bucket hay que copiarlas en img/alerts/. En local, las maquetas siguen usando ../../img/ dentro de su proyecto.

El recorrido

Cuatro etapas, una carpeta por etapa

Todo ocurre dentro de la carpeta del proyecto. Cada etapa deja su resultado en su carpeta numerada, dentro de la subcarpeta de su idioma (en/ o es/). El número es el orden real del proceso: el HTML nunca salta una etapa.

1
1_maqueta/en · es Maqueta desde Figma, con imágenes optimizadas en .png/.jpg y el .txt de observaciones. /maquetar-figma
2
2_entrega/en · es HTML para el desarrollador, con las imágenes en URL de PRD. /entregar-dev
3
3_integrado/en · es Devuelto por el desarrollador, con las variables agregadas. lo guardas tú
4
4_bucket/dev · qa · prd / en · es Una versión por ambiente e idioma, lista para subir. /publicar-ambientes
↺

Entre la etapa 2 y la 3 trabaja el desarrollador. Recibe los dos HTML de 2_entrega/, agrega las variables y te los devuelve. Guardas cada uno en 3_integrado/, en la carpeta de su idioma, y ahí haces los ajustes visuales que falten. Un mailing solo informativo, sin variables, también pasa por 3_integrado/.

Dónde está cada cosa

Carpetas de un proyecto

Cada carpeta de HTML tiene una subcarpeta por idioma, también dentro de cada ambiente del bucket. El archivo se llama igual en ambos idiomas.

CarpetaContenidoRutas de imágenes
proyecto.jsoncarpetaImagenes: subcarpeta de img/ en el bucket (ej. alerts/). Se pregunta la primera vez.—
1_maqueta/en · es/<nombre>-local.html: la maqueta generada desde Figma. <nombre>-local.txt: observaciones para diseño (erratas, fuentes, pendientes).Relativas ../../img/
2_entrega/en · es/<nombre>.html para el desarrolladorPRD + carpetaImagenes

En la raíz quedan ref/ (referencias compartidas), ambientes.json y scripts/: optimizar.mjs (PNG/JPG → .png o .jpg optimizado), rutas.mjs (entrega y publicación) y proyecto.mjs (resuelve la carpeta del proyecto).

Cómo se usa

Los skills

Se invocan en Claude Code escribiendo su nombre. Cada uno te pregunta solo lo necesario y, al terminar, te indica el siguiente paso.

/maquetar-figmapaso 1 Figma EN + ES → 1_maqueta/en · es + .png/.jpg
Te pide
  • Proyecto (ej. alerts → mailings-alerts/). Muestra los que ya existen.
  • Carpeta destino de imágenes en el bucket (ej. alerts/). Si el proyecto ya la tiene, solo pide confirmarla.
  • Dos links de Figma con Copy link to selection, uno del frame en inglés y otro del frame en español. Seleccionando solo el frame del mailing.
  • Nombre del mailing con guiones entre partes y camelCase dentro de cada parte: alert-newFees, alerts-optOut-freeTrial.
Qué hace
  1. Revisa todas las maquetas de ref/ y toma su estructura de tablas, comentarios y estilos.
  2. Lee el diseño en inglés por secciones y revisa que las fuentes sean Arial. Del español toma los textos y detecta si alguna sección cambia de medida.
  3. Te muestra qué bloque usará para cada sección de Figma.
  4. Propone sugerencias y espera tu aprobación.
  5. Exporta las imágenes a 2x y las guarda optimizadas como .png o .jpg (el que pese menos) con prefijo e-. Las iguales en ambos idiomas se exportan una vez; las que llevan texto, una por idioma.
  6. Escribe un HTML y un .txt por idioma, los abre con Edge y compara cada uno con su Figma.

Calidad de imagen: prueba calidades de 75 a 100 y, por formato, elige la más baja sin pérdida visible (PSNR de 40 dB o más). Compara PNG sin pérdida, PNG con paleta y JPG (este solo si la imagen no usa transparencia) y usa el más liviano. Nunca .webp: Outlook de escritorio para Windows no lo muestra.

/entregar-devpaso 2 1_maqueta/ → 2_entrega/en · es
Te pide
  • El proyecto y qué mailing de 1_maqueta/ entregar.
Qué hace
  • Genera un HTML por idioma con las imágenes en la URL de PRD + carpetaImagenes (ej. …/img/alerts/), para que el desarrollador vea el render.
  • Si alguna imagen no es .png/.jpg o no está en el img/ del proyecto, no genera nada y te la lista.
  • Lista las imágenes que deben estar subidas en PRD, en img/<carpetaImagenes>.
npm run mail:entregar -- --proyecto alerts --nombre <nombre>
# solo un idioma
npm run mail:entregar -- --proyecto alerts --nombre <nombre> --idioma es
/publicar-ambientespaso 3 3_integrado/ → 4_bucket/dev · qa · prd
Te pide
  • El proyecto y qué mailing de 3_integrado/ publicar.
  • Qué ambientes e idiomas. Por defecto, todos.
Qué hace
  • Lista las variables de cada idioma para que confirmes que es la versión del desarrollador y que coinciden entre en y es.
  • Cambia solo las URLs de imágenes por las del ambiente + carpetaImagenes. No toca variables ni contenido, y no duplica la subcarpeta si el HTML ya la trae.
  • Rechaza archivos que no estén en 3_integrado/en/ o 3_integrado/es/.
npm run mail:publicar -- --proyecto alerts --nombre <nombre>
# solo un ambiente
npm run mail:publicar -- --proyecto alerts --nombre <nombre> --env qa
/optimizar-imagenesauxiliar PNG/JPG suelto → .png/.jpg en img/
Te pide
  • El proyecto, qué imágenes optimizar y con qué nombre deben quedar.
Qué hace
  • Agrega o reemplaza imágenes después de maquetar: una imagen corregida por diseño, un logo nuevo.
  • Los originales nunca se guardan en img/.
  • Elige por imagen el formato más liviano: PNG con paleta, PNG sin pérdida o JPG (solo sin transparencia).
  • --force reemplaza la imagen con ese nombre en cualquier extensión y borra la anterior. Si la extensión cambió, actualiza el src en las maquetas.
npm run img:optimizar -- --proyecto alerts --dir <carpeta-con-png>
# reemplazar una imagen existente (borra la anterior)
npm run img:optimizar -- --proyecto alerts --files <ruta>/e-banner-es.png --force
/observaciones-htmlsolo a pedido .txt → página scrollytelling en obs/
Te pide
  • El proyecto.
  • Qué mailings incluir, con casillas. Cada uno indica si es nuevo o en qué fecha ya se observó.
Qué hace
  • Mailing fijo a la izquierda y observaciones a la derecha, con una línea animada que apunta al lugar del correo.
  • Faltas de ortografía en cian. Un solo HTML, con maquetas e imágenes embebidas.
  • Guarda <proyecto>/obs/observaciones-AAAA-MM-DD.html. Nunca sobrescribe: si ya hay una ese día, agrega -2, -3…
  • Solo corre cuando lo invocas; Claude no lo usa por su cuenta.
Al maquetar

Manda Figma

El diseño se respeta tal cual. Las sugerencias del skill son informativas y solo se aplican si las apruebas.

Cada idioma con su diseño

Los textos en inglés y español salen de su propio link de Figma. El skill no traduce.

Todo en Arial

Si Figma trae otra fuente, el skill te avisa para que lo corrija el diseñador; no la cambia por su cuenta.

Esquinas redondeadas

Se mantienen. Producto sabe que en Outlook de escritorio se ven rectas.

Enlaces con href="#"

En botones y textos de acción. Las URLs y las variables las pone el desarrollador; el skill no inventa ninguna.

Dominios y correos como enlace

Un dominio escrito en el diseño va con https:// y un correo con mailto:, con la misma apariencia: color, peso y sin subrayado.

Solo .png / .jpg

Optimizados, el formato que pese menos; nunca .webp (Outlook de escritorio no lo muestra). Ilustraciones compuestas en una sola imagen; íconos repetidos, un .png transparente reutilizado.

Configuración

URLs por ambiente

Viven en ambientes.json, en la raíz del repositorio, y son comunes a todos los proyectos. Si cambia un bucket, se edita solo ese archivo; los skills no preguntan URLs. A cada URL se le agrega la carpetaImagenes del proyecto.json (ej. alerts/).

AmbienteURL base de imágenes
devhttps://itl-0003-portal-dev-s3-pub-templates-03.s3.eu-south-2.amazonaws.com/img/
qahttps://itl-0003-portal-qa-s3-pub-templates-02.s3.eu-south-2.amazonaws.com/img/
prd entregahttps://itl-0003-portal-prd-s3-pub-templates-02.s3.eu-south-2.amazonaws.com/img/

"entrega": "prd" define qué URLs lleva el HTML que recibe el desarrollador, y "idiomas": ["en", "es"] define las subcarpetas de idioma.

Mejorar el resultado

Agregar referencias

Copia a ref/ el HTML de un mailing aprobado para que /maquetar-figma aprenda nuevos patrones: tablas de datos, varias columnas u otros pies. Esa carpeta es común a todos los proyectos. El skill revisa todos sus archivos en cada maquetación y usa como base el más parecido al diseño.
